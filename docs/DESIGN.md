# Design brief

For designers building innards.app and for anyone touching the app's UI. Everything in §1–§8 is taken from the code (`src/app.css`, `src/lib/components/*.svelte`, `crates/innards-core/i18n/en.json`); §9 is the website brief.

## 1. Name and meaning

**Innards** — the insides of a thing; what you find when you open it up. Capitalised in the app (`TopBar.svelte` wordmark, `tauri.conf.json` `productName`). It is deliberately a plain, slightly earthy English word rather than a coined brand: the product opens the machine and tells you what is inside, and the name should feel like something you would say out loud.

Tagline (README, `tauri.conf.json` `shortDescription`, `site/public/index.html` H1): **Look inside your machine.**

The one-liner (press kit): *Innards looks inside your computer and tells you, in plain language, what's wrong, what it's still good for, and what's actually worth buying.*

## 2. Voice and tone

The product speaks in short declarative sentences, names the part and the number, and says what to do. It never sells, never scares, and is willing to say "keep it, buy nothing". Every report line exists at three reading levels, taken verbatim from `crates/innards-core/i18n/en.json`:

| Level | Audience | `memory.no_swap` | `storage.system_hdd` |
|---|---|---|---|
| **Plain** | Someone who does not want jargon. Explains the consequence, not the mechanism. | "Your computer has 16 GB of memory and no backup space on disk. When memory runs out, the system has no choice but to close programs abruptly." | "The computer starts and loads programs from an old-style spinning disk (WDC WD10, 931 GiB). This is the single biggest thing slowing it down." |
| **Informed** *(default)* | A comfortable computer user. Light vocabulary, a number or two, the trade-off. | "There is no swap space at all. With 16 GB RAM and 12.3% currently free, a memory spike will trigger the out-of-memory killer instead of slowing down gracefully." | "The OS is on an HDD (WDC WD10, 931 GiB). Replacing it with an SSD makes everything feel 3–10× faster — the best upgrade money can buy." |
| **Expert** | A systems engineer. Field names, thresholds, the mechanism, raw evidence attached. | "swap_total = 0. Available memory is 12.3% of 16 GB. Without swap the kernel cannot reclaim anonymous pages under pressure, so the OOM killer fires on the first sustained spike. zram is the low-cost fix; a swapfile as a second tier prevents hard kills." | "System disk WDC WD10 (931 GiB) is rotational. Random 4K IOPS ~100 vs ~50k+ on any SSD." |

Other fixed phrases that set the tone:

- Severity headings: **Needs attention now · Worth fixing · Good to know · Working well** (`severities`). Never "Errors" or "Critical".
- Grades: **Not suitable · Struggles · Workable · Good · Excellent** (`grades`).
- Recommendation kinds: **Free fix · Upgrade · Service · Replace · No purchase** (`rec_kinds`); impacts: **Small gain · Noticeable gain · Big gain**.
- Verdicts: "Nothing needs your attention. This machine is in good shape." / "No emergencies, but 3 thing(s) are costing you performance or reliability." / "One issue needs attention soon, plus 5 smaller one(s)."
- Footer of every export: "Generated by Innards — the report stays on your machine."
- Scanning screen: "Looking inside…" / "Reading CPU, memory, drives, battery and sensors. Nothing leaves this machine."

Rules for new copy: second person ("your drive"), present tense, numbers with units, one idea per sentence, no exclamation marks, no emoji in product text (the only emoji are the flag glyphs in the language menu). Spanish is a full peer, not a translation afterthought; write English so it translates.

## 3. Logo

`src/lib/components/Logo.svelte` — a **chip outline with a heartbeat trace through it**: hardware plus health.

- 32×32 viewBox. A rounded square (`rect x=6 y=6 w=20 h=20 rx=4`, stroke 2.2) with three short pins on each side (stroke 2, round caps) reads as an IC package.
- Through the middle runs an ECG-style polyline `M9.5 16.5h3l1.8-4.5 2.6 8 2-3.5h3.6` (stroke 2.2, round joins) in `var(--accent)`; the chip itself is `currentColor`, so the mark inherits text colour and works on paper or dark ground with a single accent hue.
- Rendered at 26 px in the top bar next to the wordmark "Innards" (700 weight, 16 px, letter-spacing −0.02 em), at 48 px pulsing on the scanning screen. `site/public/favicon.svg` is the same mark on a `#f7f5f1` rounded tile with the ink and accent colours baked in.
- App icons in `src-tauri/icons/` (32, 128, 128@2x PNG; `.icns`; `.ico`; Windows Square logos) — regenerate with `pnpm tauri icon <1024px.png>` from a master that keeps the same mark.

Do not add gradients, a second colour, or a wordmark lock-up variant without updating the component; the mark is intentionally monoline so it survives 16 px.

## 5. Typography, spacing, radius, shadow

- `--font`: `-apple-system, BlinkMacSystemFont, "Segoe UI Variable", "Segoe UI", Inter, Roboto, "Helvetica Neue", Arial, sans-serif` — the system stack; nothing is downloaded.
- `--mono`: `"SF Mono", "Cascadia Code", "JetBrains Mono", Menlo, Consolas, monospace` — evidence blocks, license and API keys, `<code>`.
- Base 14 px / 1.5, antialiased, `font-variant-numeric: tabular-nums` everywhere (numbers align in specs and costs).
- Headings weight 650, letter-spacing −0.01 em: `h1` 22 px (24 px in the report hero), `h2` 16 px, `h3` 14 px. Eyebrows and `<dt>` labels: 11 px, uppercase, 600, letter-spacing 0.06–0.08 em, `--ink-3`. Small text 12 px; evidence 11.5 px mono.
- Radii: `--radius` 12 px (cards), `--radius-sm` 8 px (buttons, inputs, evidence, paywall), 999 px (segments, pills, chips).
- Shadow: `--shadow` `0 1px 2px rgba(0,0,0,.04), 0 4px 16px rgba(0,0,0,.05)` light / `0 1px 2px rgba(0,0,0,.3), 0 6px 20px rgba(0,0,0,.35)` dark. Cards have a 1 px `--line` border *and* the shadow.
- Spacing rhythm: page padding 20 px 28 px; grid gaps 22 px between sections, 10–12 px between cards in a list, 6 px inside a card; card padding 12–22 px. Content max-width 1180 px (report, advisor), 720 px (settings).
- Motion: `.fade-in` 250 ms ease-out (opacity + 4 px rise) on view mount; ring arc 800 ms; capability bar width 600 ms; button press 1 px translate. All disabled under `.no-anim` (screenshot mode).

## 7. Layout of the three views

**Report** (`Report.svelte`) — max 1180 px, centred.
1. Hero card, three columns `auto 1fr auto`: health ring · eyebrow "INNARDS REPORT" + machine name (h1 24 px) + verdict + "Export Markdown" button · spec list. Under 980 px the spec list drops to a full-width row.
2. Two columns `minmax(0,1fr) 340px`, gap 22 px: findings grouped in severity order (critical → warning → info → good), each group a heading + stacked finding cards; the aside is sticky (`top: 8px`) and holds the capability card then the narrative card. Under 980 px the aside stacks below.
3. At expert level, a "Probe notes" list follows the findings.

**Upgrade advisor** (`Advisor.svelte`) — max 1180 px.
1. Intro card: "Upgrade advisor" + one sentence.
2. Supporter paywall (full width) when the tier is free.
3. Two cards side by side (`1fr 1fr`): the multi-select questions "What do you use this machine for?" and "What bothers you about it?" as chip groups.
4. Before results: a right-aligned primary "Show recommendations" button (260 px min), disabled until a use is picked and the tier allows.
5. Results: heading + Cards/Visual segment; then the recommendation grid (`auto-fill, minmax(360px, 1fr)`) or the impact map with the selected card beneath; a compact Pro paywall below the results when not Pro.
6. "REFINE" eyebrow and three single-select cards (`1fr 1fr 1fr`): budget, when, portability. Changing any answer re-runs the advisor live once results exist.

**Settings** (`Settings.svelte`) — max 720 px, stacked cards: License (tier line, key input + Activate) · Narrated summaries (privacy sentence, key input) · Analysis (SMART elevation checkbox with explanation, shopping region select) · Team & Enterprise (Threadwise URL, `tw_` key, machine label, auto-upload checkbox, "Upload report now", disabled below Team with a one-line pointer) · Save button and the version line "Innards 0.1.0 · core 0.1.0 · linux".

Window: 1080×760 default, 720×520 minimum (`tauri.conf.json`). The layout is designed for ≥ 980 px; below that it stacks rather than shrinks.

## 9. Website brief — innards.app

### Design mode — run the real UI without Rust

Designers can open the exact app UI in a browser:

```bash
git clone https://github.com/buengenio/innards && cd innards
pnpm install
pnpm dev            # http://localhost:1420
```

Then compose a URL from a path (`/` report, `/advisor`, `/settings`) and parameters: `http://localhost:1420/advisor?tier=pro&lang=es&level=expert&demo=1`

| Param | Values | Effect |
|---|---|---|
| `tier` | `free` (default) `supporter` `pro` `team` `enterprise` | Which paywalls and buttons show |
| `lang` | `en` `es` | Language of the report and chrome |
| `level` | `plain` `informed` `expert` | Reading level |
| *(path)* | `/` `/advisor` `/settings` | Which view opens |
| `demo` | `1` | On `/advisor`, pre-fill answers and run |
| `view` | `visual` | With `demo=1`, open the impact map |
| `snap` | `1` | Deterministic load for screenshots (no delays, no animation) |

Dark theme follows the OS setting; switch the OS appearance or use DevTools → Rendering → "Emulate CSS prefers-color-scheme". Screenshot recipe in `docs/AGENTS.md`.
